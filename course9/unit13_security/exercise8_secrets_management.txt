Secrets Management - Handling Credentials Safely

WHAT ARE SECRETS?
-----------------
Sensitive data that grants access:
- Database passwords
- API keys
- JWT secret keys
- Encryption keys
- OAuth client secrets
- Third-party service credentials


NEVER DO THIS
-------------
❌ Hardcode secrets in code:
SECRET_KEY = "my-super-secret-key-123"
DB_PASSWORD = "postgres123"

❌ Commit secrets to git:
# config.py (committed to repo)
API_KEY = "sk_live_abc123..."

❌ Share secrets in plain text:
- Email
- Slack
- Documentation


WHY IT'S DANGEROUS
------------------
- Code is version controlled (git history)
- Repos get leaked/hacked
- Shared with everyone who has code access
- Can't rotate secrets without code changes
- Different secrets for dev/staging/prod


SOLUTION 1: ENVIRONMENT VARIABLES
----------------------------------
Store secrets outside code, in environment.

.env file (NEVER commit to git):
```
DATABASE_URL=postgresql://user:password@localhost/db
SECRET_KEY=your-secret-key-here
STRIPE_API_KEY=sk_live_abc123
```

.gitignore (ALWAYS add .env):
```
.env
.env.local
.env.production
*.key
*.pem
```

Load in code:
```python
import os
from dotenv import load_dotenv

load_dotenv()  # Load .env file

DATABASE_URL = os.getenv("DATABASE_URL")
SECRET_KEY = os.getenv("SECRET_KEY")
```

Production (set via platform):
- Heroku: heroku config:set SECRET_KEY=...
- AWS: Environment variables in Lambda/ECS
- Docker: docker run -e SECRET_KEY=...


SOLUTION 2: SECRET MANAGEMENT SERVICES
---------------------------------------
For production, use dedicated services:

AWS Secrets Manager:
- Encrypted storage
- Automatic rotation
- Audit logging
- Fine-grained access control

HashiCorp Vault:
- Centralized secret storage
- Dynamic secrets
- Encryption as a service

GCP Secret Manager, Azure Key Vault, etc.


ROTATING SECRETS
----------------
Change secrets periodically or when compromised.

With environment variables:
1. Generate new secret
2. Update environment variable
3. Restart application
4. Old secret stops working

With secret management service:
- Automatic rotation
- Both old and new valid during transition
- Zero-downtime rotation


DEVELOPMENT VS PRODUCTION
--------------------------
Different secrets for each environment!

Development (.env.local):
DATABASE_URL=postgresql://localhost/myapp_dev
SECRET_KEY=dev-secret-not-for-production

Production (environment variables):
DATABASE_URL=postgresql://prod.server/myapp_prod
SECRET_KEY=securely-generated-production-key


GENERATING SECURE SECRETS
--------------------------
Don't use weak/guessable secrets!

Bad:
SECRET_KEY = "secret"
API_KEY = "mykey123"

Good (random, strong):
```python
import secrets
SECRET_KEY = secrets.token_urlsafe(32)
# Output: 'dQw4w9WgXcQ_r2d2_k7JQ9WgXcQ8w4k7J'
```

Or use: openssl rand -hex 32

-------------------------

✅ Add .env to .gitignore

COMMON MISTAKES
---------------
❌ .env.example with real secrets
  Should have placeholder values only:
  DATABASE_URL=postgresql://user:password@localhost/db

❌ Secrets in error messages
  print(f"Failed to connect with password {password}")
  Logs now contain password!

❌ Secrets in URLs
  https://api.example.com?api_key=secret123
  Logged in web server access logs

❌ Sharing secrets via email/chat
  Use secret sharing tool (1Password, etc.)


LOGGING SAFELY
--------------
Never log secrets:

Bad:
logger.info(f"Connecting to {DATABASE_URL}")

Good:
logger.info("Connecting to database")

Bad:
logger.error(f"Auth failed with token {token}")

Good:
logger.error("Auth failed", extra={"token_prefix": token[:8]})


EXAMPLE STRUCTURE
-----------------
.env (git-ignored):
DATABASE_URL=postgresql://localhost/myapp
SECRET_KEY=abc123xyz789
STRIPE_KEY=sk_test_...

.env.example (committed):
DATABASE_URL=postgresql://user:password@localhost/dbname
SECRET_KEY=your-secret-key-here
STRIPE_KEY=sk_test_your_stripe_key

config.py:
import os
from dotenv import load_dotenv

load_dotenv()

DATABASE_URL = os.getenv("DATABASE_URL")
if not DATABASE_URL:
    raise ValueError("DATABASE_URL not set")

.gitignore:
.env
.env.local
*.key


THE RULE
--------
Secrets don't belong in code.
Use environment variables + .gitignore.
Different secrets for each environment.
Rotate regularly. Never log.
